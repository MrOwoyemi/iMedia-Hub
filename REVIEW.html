Code & UX Review

iMedia Hub

A GCSE Creative iMedia revision dashboard: 82 pages, 260 multiple-choice questions, 140 flashcards and three drag-and-drop games, all served from one HTML file and one 568 KB script. The teaching content is strong. The delivery has three problems that stop a student using it at all on a phone.

Blockers

Each of these makes a whole slice of the site unusable right now. Nothing else on this page matters as much.

Blockerstyle.css:979
script.js:8748

There is no way to open the menu on a phone

Below 768 px the sidebar is pushed off-screen and only comes back when something adds .sidebar-open. The function that adds it, toggleNav(), is never called from anywhere — there is no hamburger button in index.html. I measured the sidebar sitting at left: -240px on a 390 px viewport with no trigger in the DOM.

mobile sidebar box → {"left":-240,"right":0,"width":240} any toggleNav trigger in DOM? → false

A student on a phone lands on the dashboard and can reach the four Quick Start cards and nothing else — no topic areas, no marking criteria, no resources. Given who this is for, the phone is the main device.

Fix Add a hamburger button to the topbar that calls toggleNav(), shown only under 768 px, plus a tap-to-dismiss overlay. The CSS and the function both already exist — only the button is missing.

Blockerstyle.css:979

The mobile search box is 62 pixels wide

The search container shrinks with the topbar but the input has no minimum width, so on a 390 px screen it renders at 62 × 40 px — you can see the magnifier and about three characters. With the sidebar unreachable, search is the only remaining route to a page, and it is not typeable.

Fix Under 768 px, either give the input flex: 1 with a sensible min-width, or collapse search to an icon that expands to full width when tapped.

Blockerscript.js:156, 252

Both dashboard panels have expired

The exam date is hardcoded to 8 June 2026 and the eleven homework items run out on 27 May 2026. Today is August. The countdown now reads “Exam completed” and homework reads “No homework yet. You're all caught up! 🎉” — so half of the dashboard is permanently blank until someone edits the source.

The logic is fine; the data has no refresh path. There is also an unused Easter/half-term holiday-week calculation in createExamCountdownHTML() that will need re-dating every year.

Fix Move exam dates and the homework bank into a small dated config at the top of the file (or a separate data.js), and make the “Homework” panel’s + button actually add items to localStorage so the sheet stays current without a code edit.

Bugs

Reproducible defects. The first one throws a real exception; the rest quietly do the wrong thing.

Bugscript.js:9632

Leaving a timed test mid-question throws an error every second

The 30-second timer in Full Exam Mode is only cleared by quizShowMenu(). Click a sidebar link instead and the interval keeps ticking against DOM nodes that loadContent() has already replaced. Confirmed in the browser:

[pageerror] Cannot set properties of null (setting 'innerText') [pageerror] Cannot set properties of null (setting 'innerText')

It repeats once a second forever, and when the count hits zero it calls quizHandleAnswer() against a question the student is no longer looking at.

Fix Call clearInterval(quizTimer) at the top of loadContent().

Bugscript.js:261

Dark mode makes the exam card unreadable — 1.11:1

The countdown card carries an inline style="background: #DCFCE7", a light mint green. In dark mode the text colour flips to the theme’s near-white while that background stays put. Measured contrast on the card title is 1.11:1, against the 4.5:1 minimum — the text is effectively invisible.

exam card title (dark) fg #ECE6F3 on bg #DCFCE7 → 1.11:1 exam card date (dark) fg #BFB5CC on bg #DCFCE7 → 1.79:1

This is the visible symptom of a wider pattern: there are 1,109 inline style= attributes in script.js, and every hardcoded colour among them is invisible to the dark theme. Light mode itself is fine — I measured 5.3–5.9:1 across body text.

Fix Replace the inline colour with a .exam-item.completed class and give it a body.dark-mode variant. Then sweep the other inline colours into CSS custom properties so both themes are defined in one place.

Bugscript.js:8624

Search only matches internal page IDs, not titles

handleSearch() filters Object.keys(contentData) — the raw keys, like r093_3_3b. So typing “media”, the single most likely thing a student searches on this site, returns no pages at all. Typing “r093” returns twenty results labelled Page: r093 3 3b, which tell the reader nothing.

handleSearch('media') → Term: Traditional Media | Term: New Media | Term: Media Code (zero page results)

Two smaller faults in the same function: keyword hits all navigate to card 1 of the flashcard deck rather than the matched term, and t.replace('_', ' ') replaces only the first underscore. The dropdown also never closes — no blur handler, no clear on select.

Fix Give each page a title in a lookup table and search that, showing the title in results. Add /g to the replace, close the dropdown on select and on blur, and jump keyword hits to their card index.

Bugindex.html:35, 48, 61

The three unit hub pages need a double-click to reach

R093, R094 and R096 each open their overview page via ondblclick, while a single click toggles the submenu. Nothing on screen says a hub page exists, double-click is not a gesture on touch, and a double-click on desktop also fires the single-click handler twice — so the submenu opens and shuts on the way through.

Fix Split the row: the label navigates to the hub, a separate chevron button toggles the submenu. That is what the markup already looks like.

Bugindex.html:118
script.js:371

“Day Streak” is a number that never moves

The topbar pill hardcodes 1, the dashboard stat card hardcodes 0, and no code writes to either. Two different fake values for the same metric, side by side on the same screen. The XP, level, rank and achievement counters next to them are all real and correctly persisted — which makes the dead one more conspicuous, not less.

Fix Either track it (store last-visit date, bump or reset on load) or remove both — a gamified dashboard loses credibility fastest on the counter that obviously isn't counting.

Bugscript.js:9547, 9553

Quiz shuffling uses a biased sort

Questions and answer options are shuffled with .sort(() => 0.5 - Math.random()), which is not a uniform shuffle — comparison sorts with a random comparator leave items near their original positions more often than chance. In a 25-question exam drawn from 260, the same questions surface disproportionately.

A correct Fisher–Yates implementation, shuffleArray(), already exists at line 8701 for the flashcards.

Fix Call the existing shuffleArray() in all three places.

Bugscript.js:8870, 8708

Two unguarded null dereferences

drop() calls draggedElement.getAttribute() without checking the element resolved — dragging anything that isn't one of the game tiles (a link, selected text, a file) onto a drop zone throws. And flipCard() reads card.style with no null check, unlike its siblings nextCard() and prevCard(), which both guard correctly.

Fix Early-return when the element is missing, in both.

Bugscript.js:8985+

Four past-paper questions are duplicated inside their own topic

The four past-paper sets hold only 6–9 questions each, and each one contains a repeat — so a student sees the same question twice in a very short session.

TA1 "Which one of the following is a traditional media product?" TA2 "Which of these is an example of primary research?" TA3 "Which legislation covers the collection and storage of personal user data?" TA4 "Which file format is best for a vector logo... transparent background?"

Worth saying what I did not find: across all 260 multiple-choice questions, every stated answer appears in its own options list, and no option is duplicated within a question. The 140 flashcards have no repeated terms. The bank is in good shape apart from these four.

Fix Delete the four repeats, or replace them so each past-paper set keeps its length.

Accessibility and polish

The whole app contains zero aria-* attributes, zero roles and zero tabindexes. For a school-issued resource that is likely to matter beyond good practice.

A11yscript.js, 204×

Interactive elements are divs with onclick

There are 204 inline click handlers, and every external link — the YouTube revision videos, the iMediaTrainer link — is a div calling window.open(). Not one of them is an <a href>. That means no keyboard access, no tab focus, no “open in new tab”, no copy-link, no middle-click, and popup blockers can swallow them.

Fix Make anything that navigates an <a> with a real href, and anything that acts a <button>. Both come with keyboard support for free.

A11yscript.js:8802

Page changes are silent to a screen reader

loadContent() swaps innerHTML and moves on. Focus stays wherever it was, no heading is announced, and there is no live region — so a screen-reader user clicks a topic and hears nothing change. There is also no skip link past the sidebar.

Fix After injection, move focus to the new <h1> (with tabindex="-1") and set document.title. Add a skip link as the first focusable element.

A11yindex.html:35, 111

Menus and controls carry no state or labels

The three submenu toggles have no aria-expanded, so their open/closed state is invisible to assistive tech. The search input has a placeholder but no label. The theme toggle and the streak pill are bare emoji and digits with no accessible name. Sixteen href="#" links jump the page to the top and append # to the URL on every click.

Fix Add aria-expanded to the toggles, an aria-label to search and the theme button, and swap href="#" for real targets or <button>.

UXmeasured, 390px

Mobile layout details

The floating Back button sits on top of page content — I found it overlapping an <h2> on the Quiz Trainer page. Two pages scroll sideways on a 390 px screen (r093_4_1 at 449 px, timeline_game at 415 px). All twelve submenu links are 38 px tall, just under the 44 px touch-target guideline.

Fix Add bottom padding to #main-content to clear the button, let the wide tables scroll inside their own container, and round the submenu rows up to 44 px.

UXscript.js:8745

No URLs, no browser Back, no bookmarks

Navigation is a JavaScript array. The browser Back button leaves the site entirely, a refresh always dumps you on the Dashboard, and there is no way to send a classmate a link to a specific topic — which is exactly what a revision site gets used for. The custom Back button also labels itself from the raw key, so it reads ← Back to R093 3 3B.

Fix Use history.pushState() with a hash per page and read it on load. That gives real Back, refresh-in-place and shareable links in about fifteen lines, and fixes the label as a side effect once pages have titles.

Contentscript.js

Legislation is cited without years

The Data Protection Act, the Copyright, Designs and Patents Act and the Equality Act are all referenced by name only. OCR mark schemes generally credit the year, and students who learn the name without it lose the easy mark.

Separately, resolution units are inconsistent across the material — 300 DPI appears 19 times and 300 PPI twice; 72 PPI 15 times and 72 DPI twice, plus one 300DPI with no space. Both are defensible in an answer, but a revision resource should pick one and be consistent about which is print and which is screen.

Fix Add the years (1988, 2018, 2010) and standardise on DPI for print output, PPI for screen.

Perfscript.js, 568 KB

Every student downloads all 82 pages to read one

script.js is 568 KB across 9,719 lines, and 8,300 of those are one contentData object holding 82 pages of HTML as template literals. All of it is parsed before first paint. On school wifi or a phone on 4G that is the slowest part of the site by a wide margin.

Fix Split contentData, the quiz bank and the flashcards into separate files and load them on demand. Even without a build step, three <script> tags with defer would let the dashboard paint before the quiz bank arrives.

Repo1.3 MB

Dead weight in the repository

images.zip (962 KB) is an exact duplicate of the eleven loose image files already committed at the repo root — nothing loads it. Four of those images are referenced nowhere at all: both wireframe JPGs and both flowchart PNGs, another 316 KB. Together that is over half the repository’s working tree.

Loose ends: the root README.md is one line, there is no favicon (the browser 404s on /favicon.ico), and there is no meta description.

Fix Delete images.zip, move the images into an images/ folder, drop the unreferenced four or wire them into the pre-production pages where they clearly belong, and add a favicon plus a paragraph of README.

Codescript.js:332, 8617, 8753

Small dead code

The saved theme is applied twice — once by applySavedTheme() and again by a duplicate inline block 8,000 lines later. setActiveNav() has an else if branch containing only a comment, and submenu items consequently never show an active state. quizShowHint() uses alert(), which on mobile Safari blocks the whole page behind a system dialog.

Fix Delete the duplicate theme block and the empty branch, give submenu links their own active class, and render hints into the feedback area instead of an alert.

What holds up well

Said plainly, because the list above is long and the foundation underneath it is better than the list suggests.

  • ✓Nothing is broken in normal navigation. I walked all 82 pages in a headless browser: no runtime exceptions, no failed requests, no 4xx. For 9,700 hand-written lines with no build step and no framework, that is genuinely uncommon.
  • ✓The wiring is consistent. All 83 loadContent() targets resolve to real pages, there are no orphan pages, every one of the 25 inline handler names resolves to a defined function, and there are no duplicate element IDs beyond one deliberate reuse across two game pages.
  • ✓The content is the real asset. 260 multiple-choice questions with per-answer explanations, six long-answer questions with full indicative-content mark schemes, 140 keyword definitions and three drag-and-drop games — all mapped to R093/R094/R096 topic areas. The mark-scheme wording reads like it came from someone who marks these papers.
  • ✓The gamification is coherent. XP tiered by activity (10 topic / 20 exam / 50 past paper), 100 XP levels, seven rank bands, three achievement counters — persisted properly and refreshed on every page load. The one-award-per-activity guards using dataset.completed are a nice touch.
  • ✓The visual design is good. The plum-and-white dashboard is clean and current, spacing is consistent, and light-mode contrast measures 5.3–5.9:1 throughout. Dark mode is well judged apart from the inline-colour leak above.

The order I'd do it in

  1. Hamburger button and mobile search width. Perhaps twenty lines. It takes the site from unusable to usable on the device most students will open it on.
  2. Re-date the exam and homework data. Half the dashboard is currently blank; this fills it back in.
  3. Clear the quiz timer in loadContent(), fix the dark-mode exam card. One line and one class — the only two defects that are actively visible to a student mid-session.
  4. Make search find pages by title. Search is the fallback route through the site, and right now it cannot find the word “media” on a media revision site.
  5. Real links and buttons instead of div onclick. The largest job on the list, and the one that clears most of the accessibility findings at once.
  6. Split the script and clean the repo. Do this when the rest is settled — it changes no behaviour but makes everything after it cheaper.
